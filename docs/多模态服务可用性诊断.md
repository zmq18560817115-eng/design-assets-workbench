# 多模态服务可用性诊断与恢复

## P0 正式调用合同

正式蓝图拆解与最小文本探测采用不同预算。正式任务默认使用 Chat API 的
SSE 流式响应，客户端收齐所有 delta 后才解析并校验完整 JSON；流式片段、
超时结果和 fallback 均不得写成 verified。默认将图片最长边限制为 768px、
输出限制为 768 tokens、单次读取超时为 180 秒。读超时不自动重试，避免
同一张图片重复产生付费请求；认证、限流和服务端错误仍按通用调用策略处理。

可通过以下环境变量调整，但修改后必须重新执行全部门禁：

```text
VISION_CALIBRATION_READ_TIMEOUT=180
VISION_CALIBRATION_MAX_TOKENS=768
VISION_CALIBRATION_IMAGE_EDGE=768
```

以上配置不会降低 `LayoutBlueprint` 字段合同。当前 Calibration 样本实际包含
4–8 个目标区域，768 tokens 用于覆盖最多 8 个模块的完整结构化输出。

Canary 不能只凭 HTTP 成功和 Schema 合法放行。产品识别、主要文字识别、
排版模块召回、异常重叠和超时率必须同时满足 `CALIBRATION_GATES`；任一业务
质量门禁失败时，完整 Calibration 按钮保持禁用。

当模型调用连续失败时，必须先把 Calibration 标记为
`blocked_by_provider_availability`。服务可用性问题不能记作图片拆解质量失败，
fallback 也不能记作真实模型成功。

## 第一步：单次预检

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\run_provider_preflight.py `
  --manifest ..\evaluation\visual-analysis\untitled1-manifest.json `
  --output ..\evaluation\provider-availability\preflight.json `
  --smoke-count 1 --connect-timeout 10 --read-timeout 120 --max-retries 1
```

预检严格按配置、DNS/TCP/TLS、最小文本、最小图片的顺序执行。前一步失败时，
后续付费调用不会执行。报告只显示 API Key 为 `configured` 或 `missing`。

## 第二步：服务恢复冒烟

只有管理员确认部署点健康后，才执行连续三次预检：

```powershell
.\.venv\Scripts\python.exe scripts\run_provider_preflight.py `
  --manifest ..\evaluation\visual-analysis\untitled1-manifest.json `
  --output ..\evaluation\provider-availability\smoke-3.json `
  --smoke-count 3 --connect-timeout 10 --read-timeout 120 --max-retries 1
```

三次必须全部成功。任何一次失败都会立即停止，不补跑剩余调用。

## 第三步：3 张 Calibration Canary

只有 `smoke-3.json` 全部成功时才可执行：

```powershell
.\.venv\Scripts\python.exe scripts\run_visual_calibration.py `
  --manifest ..\evaluation\visual-analysis\untitled1-manifest.json `
  --output ..\evaluation\provider-availability\calibration-canary.json `
  --prompt-version visual-calibration-prompt-v3-streaming `
  --validator-version visual-calibration-validator-v2 `
  --instructions-file ..\evaluation\visual-analysis\prompt-visual-calibration-v2.txt `
  --validator-config ..\evaluation\visual-analysis\validator-visual-calibration-v2.json `
  --stage canary --readiness-report ..\evaluation\provider-availability\smoke-3.json `
  --workers 1 --timeout 180
```

脚本固定使用并发 1，并按 Ground Truth 模块复杂度选择简单、中等、复杂三张。
逐张保存；连续三次服务失败立即熔断。fallback 不计成功。

## 第四步：完整 Calibration

只有 Canary 三张全部模型调用成功、Schema 合法且无 fallback，完整运行命令才会
接受 Canary 报告作为门禁。完整运行支持断点续跑，已成功案例不会重复调用。

```powershell
.\.venv\Scripts\python.exe scripts\run_visual_calibration.py `
  --manifest ..\evaluation\visual-analysis\untitled1-manifest.json `
  --output ..\evaluation\provider-availability\calibration-full.json `
  --prompt-version visual-calibration-prompt-v3-streaming `
  --validator-version visual-calibration-validator-v2 `
  --instructions-file ..\evaluation\visual-analysis\prompt-visual-calibration-v2.txt `
  --validator-config ..\evaluation\visual-analysis\validator-visual-calibration-v2.json `
  --stage full --readiness-report ..\evaluation\provider-availability\calibration-canary.json `
  --workers 1 --timeout 180
```

Holdout 不由这些脚本执行。只有完整 Calibration 成功率、Schema/坐标合法率和版本
冻结条件全部满足后，才可通过原有密封盲测流程运行 Holdout。
