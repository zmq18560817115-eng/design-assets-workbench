# 图片拆解规则说明

本文档说明「AI视觉拆解 Agent」对一张图片的拆解逻辑与判定规则，便于团队理解与调参。

## 一、总体架构：混合模式

拆解分两层，可独立工作也可叠加：

| 层 | 负责 | 实现 | 特点 |
|----|------|------|------|
| **客观特征层** | 色板、亮度、饱和度、对比度、冷暖、边缘分布、**硬版式参数**（页边距/栅格/模块） | Pillow 从像素计算（`vision_provider.py`） | 精确、可复现、随图变化 |
| **语义/规则层** | 图片类型、行业、场景、风格、信息层级、为什么优秀、提示词 | ①启发式规则（各 Agent）② 可选真实视觉大模型 | 语义理解 |

**运行策略**：
- 未配置视觉大模型 → 语义层用**启发式规则**（离线可跑，确定性）。
- 配置了视觉大模型（`VISION_PROVIDER=openai/qwen` + `VISION_API_KEY`）→ **语义由大模型给出**，
  但**硬版式参数与真实色板仍取 Pillow 测量值**（像素测量比大模型更准），二者合并输出。
- 大模型调用失败 → 自动回退到启发式，链路不中断。

> 核心理念：**能精确测量的用测量，需要理解的用模型。**

## 二、客观特征提取规则（Pillow）

| 特征 | 计算方法 |
|------|---------|
| 主色板 | 缩略后量化到 8 色，取出现频率最高的 5 个色值 |
| 色名 | 转 HSV，按色相分红/橙/黄/绿/青/蓝/紫；饱和度<0.12 归黑/白/灰 |
| 亮度 | 所有像素明度 V 的平均 |
| 饱和度 | 所有像素饱和度 S 的平均 |
| 对比度 | 明度 V 的标准差（放大后截断到 0~1） |
| 冷暖 | 暖色相像素数 ≥ 冷色相像素数 → 暖调 |
| 繁简度 | 边缘图（FIND_EDGES）的平均强度 |
| 区域活跃度 | 边缘图按 上/中/下 三段、左/中/右 三列 分别求均值 |
| 文字密度 | 边缘强度 > 60 的像素占比 |

> 边缘图会先裁掉四周 2px，去除 FIND_EDGES 的亮边伪影，避免污染页边距检测。

## 三、语义层：启发式判定规则（阈值）

### Vision Agent —— 图片类型 / 行业 / 场景
- **类型**：竖图→海报；横图→Banner/横版主视觉；方图→产品卡
- **行业**：
  - 亮度>0.7 且 饱和度<0.35 → 美妆/生活方式
  - 含蓝/青 → 科技/互联网
  - 暖色 且 饱和度>0.4 → 餐饮/消费品
  - 亮度<0.35 → 潮流/奢侈品
  - 其他 → 泛品牌/通用

### Style Agent —— 风格标签（可叠加）
| 风格 | 触发条件 |
|------|---------|
| 高级感 | 饱和度<0.35 且（对比度>0.4 或 亮度<0.4） |
| 科技感 | 冷色 且 对比度>0.35 |
| 温暖感 | 暖色 且 亮度>0.5 |
| 年轻化 | 饱和度>0.5 且 亮度>0.55 |
| 极简 | 主色≤3 且 饱和度<0.4 |
| （均衡） | 以上都不满足时的兜底 |

品牌定位由命中的风格推导（高级感→高端品质、科技感→创新科技、年轻化→潮流客群…）。

### Design Agent —— 色彩 / 构图 / 光影 / 材质
- **色彩体系**：冷暖 + 高/中/低饱和（>0.5 / 0.3~0.5 / <0.3）+ 主色 + 主要色名
- **构图**：竖图→竖向上下分区；横图→横向左右分区；方图→居中/对称；对比度>0.45→对比强烈突出主体，否则柔和留白
- **光影**：亮度>0.7→高调通透；<0.35→低调氛围；否则中间调
- **材质**：低饱和+高亮→哑光磨砂；对比度>0.5→光泽反光；否则自然材质

### Layout Agent —— 排版（拆解重心）
- **版式类型**：
  - 繁简度<0.25 → 留白型/极简
  - 上下段活跃度差>0.12 且重心在上/下 → 分区型
  - 文字密度>0.28 → 网格型/多模块
  - 否则 → 中轴型/居中
- **对齐**：由左/中/右列活跃度判断（居中/左/右/两端网格）
- **信息层级**：由活跃度差推导（主标题/主体 → 副标题 → 正文 → 辅助信息）
- **文字/字体**（Typography）：
  - 标题处理：活跃度差大→大字号抢焦点；繁简度低→克制留白；否则图文一体
  - 字体调性：低饱和暗调→高级无衬线；暖色高饱和→圆润/手写；高对比→粗衬线；否则现代无衬线
  - 文字占比：文字密度>0.28→重文字；<0.12→以图为主；否则图文均衡

### Rule Agent —— 设计规律
综合上述维度输出「为什么优秀」与「可复用方法」，其中排版/文字层面的规律优先。

### Prompt Agent —— 绘图提示词
把拆解结果**反向拼接**成中/英文提示词，顺序为 **版式为主 → 风格为辅**。

## 四、硬版式参数算法（行/列投影）

对边缘图做投影分析：
- **行投影 / 列投影**：每行、每列的边缘强度之和。
- **活跃区间**：投影值 > 峰值×16% 视为「有内容」。
- **页边距**：内容区上/下/左/右到画面四边的距离占比。
- **模块数（纵向）**：活跃行按留白间隙（>5% 高）聚成的组数。
- **栅格列数**：活跃列按留白间隙（>6% 宽）聚成的组数。
- **内容占比**：内容边界框面积 / 画面面积。

这些是纯几何测量，随图变化、可解释（例：居中带留白的图 → 宽边距、内容占比约 36%）。

## 4.5 设计视觉概论（跨案例沉淀层）

在「逐张拆解」之上，`concept.py` 把整个案例库聚合成团队专属的《设计视觉概论》
（接口 `GET /api/concept`，页面 `/concept`）：
- **分布画像**：版式类型 / 风格 / 栅格 / 色系 / 行业 / 字体的占比分布。
- **视觉 DNA**：最常用版式、标志性风格、常用栅格、高频主色。
- **提炼的设计原则**：从高频共性自动生成的自然语言规则（例：「83% 采用留白型版式」）。
- **分行业概论**：每个行业的常用版式、风格、主色系。

随案例增多自动更新、越来越准（案例数 < 5 时会提示素材不足）。这是把「个人经验 →
企业共享 AI 视觉知识资产」真正落地的一层。

## 五、拆解重心：排版优先

- 案例**名称**、检索**标签**均以版式（版式类型/对齐/图文占比/字体）打头，风格与色彩次之。
- 前端案例详情/拆解页把「排版·文字」卡片置顶并标注「拆解重心」。

## 六、意向图生成：版式为主、风格为辅

需求生成页上传意向图后：
- 先对意向图跑完整拆解。
- 推荐标签、方向、提示词均以**量化版式参数**（栅格/模块/页边距/信息层级）为主，
  风格/色板作为次要参考。提示词结构：`【版式为主】… ; 【风格为辅】…`。

## 七、接入真实视觉大模型

配置以下环境变量即可从启发式切换到大模型语义理解（OpenAI 兼容接口）：

```bash
# 火山引擎 · 豆包视觉（Ark 方舟，OpenAI 兼容）
export VISION_PROVIDER=volcengine
export VISION_API_KEY=<火山方舟 API Key>
export VISION_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
export VISION_MODEL=<接入点ID ep-xxxx 或 doubao-vision 模型名>

# 或 OpenAI / Qwen-VL
# export VISION_PROVIDER=openai; export VISION_BASE_URL=https://api.openai.com/v1; export VISION_MODEL=gpt-4o-mini
# export VISION_PROVIDER=qwen;   export VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1; export VISION_MODEL=qwen-vl-max
```

- 只要是 OpenAI 兼容接口即可（火山引擎豆包、GPT Vision、Qwen-VL、内网自建 vLLM/LMDeploy 等），
  设好 `VISION_PROVIDER`（任意非 mock 名）+ Key + Base URL + Model 即启用；`GET /api/health` 可确认。
- 大模型只增强**语义层**；真实色板与硬版式参数仍由 Pillow 提供。
- 调用失败自动回退启发式。实现见 `backend/app/vlm.py` 与 `backend/app/agents/pipeline.py`。

### 配置真实模型后额外产出的「深度解析」
除覆盖基础语义外，模型还会输出更深的维度（存入案例、前端「AI 深度解析」卡片展示）：
目标受众、适用场景、**色彩角色**（主/辅/点缀及其作用）、**构图原理**（三分法/视觉动线/负空间…）、
情绪叙事、**专业点评**（优点+不足）、**提升建议**（可操作）。案例会标注解析来源
（`analyzed_by` = 模型名 或「启发式规则」），可在 `GET /api/health` 查看当前是否启用大模型。
